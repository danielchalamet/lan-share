# Контекст для следующей сессии Codex

Обновлено: 2026-09-12. Сначала читать этот файл; историю чата поднимать только при конкретном пробеле.

## Задача и предпочтения

Пользователь русскоязычный. Нужен запускаемый из Terminal прототип macOS → Safari на iPhone в одной Wi-Fi сети: отдельное окно/весь экран **со звуком**, плюс локальные видеофайлы. Без полноценного .app и облака. Не просить повторно разрешить уже заказанные правки. Нужны постоянная ссылка и QR в Terminal; экономить токены, не перечитывать чат.

## Где проект

Этот каталог `outputs/lan-share` — исходники и рабочая `.venv`. Архив `../lan-share.zip` — исходники без окружения и секретов. `README.md` — инструкция для пользователя. Корневой `AGENTS.md` указывает сюда.

Запуск из этого каталога: `./run.sh [--media "$HOME/Movies"] [--port 8080]`.
Остановка: Ctrl+C. run.sh устанавливает недостающие зависимости и запускает caffeinate.

## Архитектура

- capture.py: ScreenCaptureKit через PyObjC; фильтр дисплея или desktopIndependentWindow. Время CMSampleBuffer PTS переводится в monotonic через host clock; общий MediaTimeline под lock, максимум 24 BGRA-кадра; 1280 px / 24 fps.
- audio_capture.py: CoreAudio PCM 48 kHz stereo; planar/interleaved float32 или int16 → int16; PCM затем попадает в общий MediaTimeline по исходному PTS. Звук окна = всё приложение, звук экрана = системный. Микрофона нет.
- server.py: aiohttp, aiortc. H.264 программный, аудио Opus; до трёх зрителей. Нет STUN/TURN. Источник выбирают только с loopback; API/файлы требуют ключ. HTTP Range/HEAD. MediaLibrary хранит явно выбранные файлы под случайными ID; --media необязательно наполняет начальный список. Просмотр папок/add/remove только localhost + key; GET files без путей.
- playout.py: общий PlayoutClock на пару треков, буфер 150/300/500 мс (по умолчанию 300); fixed cadence 24 fps/50 audio packets; no encode-time accumulation; sample-position audio gaps, bounded history. При перегрузке общая wall-clock шкала позволяет догнать эфир, не накапливая рассинхрон.
- media_library.py: web browser папок на Mac, мультимедиа с нескольких путей; выбор в памяти до остановки; symlinks отклоняются, remove не удаляет файл с диска. Телефон обновляет список каждые 5 секунд.
- connection.py: .access-key с правами 0600, сохраняется после рестарта. scutil LocalHostName → .local-ссылка; запасной IP en0/en1. qrcode печатает терминальный QR.
- static/client.js: recvonly video+audio в одном MediaStream; кнопка «Включить звук» для Safari; localhost изначально muted против эха.
- run.sh/requirements.txt: .venv, проверки импортов, установка зависимостей. requirements-tested.txt — установленный набор.
- test_mvp.py: нативные тестовые видео/аудио буферы, реальный WebRTC loopback, HTTP авторизация/Range/файлы.

## Исправленный сбой и границы проверки

Пользователь получил SIGABRT: CGS_REQUIRE_INIT (did_initialize), SCContentFilter.initWithDesktopIndependentWindow → SLSGetDisplaysWithRect. Причина: CLI не создал соединение с WindowServer. Добавлен initialize_macos(): NSApplication.sharedApplication(), activationPolicy Prohibited, в main и перед content(), строго main thread. .app не создаётся. Apple документирует эту инициализацию: https://developer.apple.com/documentation/appkit/nsapplication/shared

На Mac: macOS 15.7.9, Apple M1, Python 3.14.7 Homebrew. Swift есть, SDK/Xcode отсутствует, поэтому Swift-сборку не использовать без нужды. ffmpeg установлен, для работы не нужен.

Пользователь подтвердил работу трансляции со звуком на физическом iPhone. Затем сообщил о залипании кадров/рассинхроне. Исправлены выявленные причины: video использовал время отправки вместо захвата и добавлял encode time к периоду; audio независимо обрезало очередь. Теперь исходные PTS + общий буфер и фиксированная шкала обеих дорожек.

Проверено после последней правки: 10 тестов (PCM planar/interleaved, video, WebRTC H264+Opus, auth/Range, persistent key/QR, общий буфер при jitter/gap/stall, ограничение памяти, динамическое добавление/удаление медиа, запрет browse/add/remove для удалённого зрителя). Через браузер проверены настройки буфера, навигация по папке и добавление выбранного тестового файла. Тестовый сервер 8091 остановлен, пользовательский 8080 не трогали.

НЕ проверено на физическом iPhone именно после правки буфера: плавность и AV sync. Предыдущее подтверждение работы не равно проверке этой версии. CGPreflightScreenCaptureAccess из Codex = False; пользователь запускает из Terminal. Пользователю нужен один перезапуск ./run.sh и обновление страницы на обоих устройствах; затем выбор файлов не требует перезапуска.

## Постоянные ссылки

Ключ сохраняется в .access-key, не читать/выводить его без задачи и не включать в архив. Ссылка .local переживает смену IP; требует Bonjour/mDNS. При смене имени Mac/порта/ключа ссылка меняется. После сбоя источник нужно выбрать заново; автоматического возобновления захвата нет. Старый клиент Safari нужно обновить после правок JS.

## Рабочий процесс

Менять эти файлы на месте. Обновлять README и этот файл при существенных изменениях. ZIP пересобирать, исключая `.venv`, `__pycache__`, `.access-key`. Не удалять пользовательские файлы. Не запускать общий git status: верхний git-корень охватывает домашний каталог; использовать только точечные пути при необходимости.

В песочнице нет сетевых bind/доступа PyPI: pip и WebRTC-тесты запускать через разрешённую эскалацию. Обычные чтения/правки доступны. Не оставлять тестовый сервер работающим без необходимости. Пользователь сам запускает ./run.sh в Terminal для правильной привязки разрешения.
